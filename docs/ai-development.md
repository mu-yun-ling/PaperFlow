# PaperFlow AI 辅助开发记录

以下按项目推进顺序整理阶段提示词、功能调整和问题修复过程。提示词均为整理稿，其中问题修复指令依据阶段验收记录补写；实现结果对应项目现有代码与测试。

## 1 项目规划与基础框架

> 我要开发一个面向大学生和科研初学者的文献阅读与笔记管理工具 PaperFlow，既用于课程实践，也考虑后续个人使用。前端采用 React、TypeScript、Ant Design 和 ECharts，后端采用 Flask、SQLAlchemy 和 SQLite，支持 Windows 本地运行。
>
> 核心流程是录入文献、标签分类、记录笔记、检索回看和查看统计。先设计数据库、REST API 和开发顺序，再实现基础框架，不要一次生成全部功能。后端按 models、routes、services 分层，前端拆分页面和组件；每阶段完成后检查运行结果，再进入下一阶段。

结果：完成应用工厂、基础数据模型、API、统一校验与错误处理，确定后续开发顺序。

## 2 核心业务与边界修复

> 继续完成文献、标签和笔记的增删改查。文献支持基本信息、阅读状态和收藏；标签与文献建立多对多关系；每条笔记必须关联具体文献，禁止空笔记。标题或 DOI 重复时应提示，删除文献后清理关联笔记和标签关系，保留其他文献使用的共享标签。
>
> 沿用现有结构，先检查已有接口再补充，不要重复创建。请实际测试正常、非法、重复及关联删除场景，发现问题后局部修复。

测试中发现超范围 ID 会引发数据库整数溢出，对应补充指令：

> 当资源 ID 或 tag_ids 超过 SQLite 整数范围时，接口出现 500。请先用测试复现，再把范围检查放到数据库查询和写入之前。不存在的路径资源返回 404，非法标签参数返回 400；失败时不能改变已有文献、标签和笔记。修复后回归正常 CRUD。

结果：修复超范围 ID，补充编辑失败回滚、笔记隔离、多对多关系及真实 HTTP 测试。

## 3 前端业务页面

> 基于现有后端完成文献列表、新增、编辑、详情、标签管理和阅读笔记页面，不重做后端。列表展示标题、作者、年份、标签、状态及更新时间，详情支持修改状态、收藏和管理笔记。
>
> API 请求统一封装，组件职责明确；加载、空数据、请求失败和删除确认都要有清楚的反馈。完成后实际操作页面，核对保存结果和接口返回是否一致。

结果：完成主要业务页面和请求层，对接真实数据库，校验及重复冲突可在页面显示。

## 4 检索与组合筛选

> 在现有文献库中增加标题、作者搜索，以及标签、年份、阅读状态、研究主题筛选，支持按年份、创建时间和更新时间排序。多个条件可以组合，结果必须来自数据库。
>
> 筛选变化后重置分页，增加清空条件入口。请覆盖单条件、组合条件、无结果、排序和翻页，确认清空后没有残留条件，特殊字符不会被误当成通配符。

结果：完成组合查询、稳定排序和分页，补充无结果、清空条件与特殊字符的验证。

## 5 阅读概览与统计

> 首页增加文献总数、未开始、阅读中和已读完数量，用 ECharts 展示状态、年份及标签统计。数据从数据库聚合，新增、删除或修改文献后应同步变化。
>
> 请额外核对：同一文献关联多个标签、多条笔记时，文献总数只能计一次；超过列表第一页的数据也必须纳入统计，空库和空年份要正确展示。

结果：文献统计按数据库全量聚合，标签数量按关联关系计算；动态更新、多关系计数和跨分页测试通过。

## 6 文件导入与字段调整

> 增加 PDF 原文及 PDF、DOCX、MD、TXT 笔记附件的上传、查看、下载、替换和删除。PDF 信息先在本地解析，预填标题、作者、年份、DOI 和摘要，由用户检查后保存；识别结果只填空字段，不覆盖已输入内容。
>
> 这里调整录入规则：标题必填，作者、年份等元信息改为选填，避免 PDF 识别不完整时无法建档。请同步修改表单、后端校验和旧数据库约束，保留已有数据及关联。

异常处理的补充要求：

> 请检查错误类型、空文件、超大文件、文件丢失、解析超时以及上传或替换中途失败。数据库失败时恢复旧文件，清理未完成的新文件；解析失败应允许手动录入，不能阻断普通文献管理。

结果：完成附件管理、无状态 PDF 预填和保留数据的升级；解析受超时限制，文件操作与数据库采用补偿处理。标题为空仍拒绝保存，作者为空可以建档。

## 7 AI 文献辅助与配置改进

> 增加独立 AIService，实现结构化论文分析、关键词建议和基于在线笔记的阅读总结。模型、服务地址和密钥可配置，长论文限制输入范围并显示来源说明。
>
> 结果先展示，关键词由用户选择后添加，总结由用户确认后另存笔记，不覆盖原摘要和已有内容。AI 未配置、超时或返回格式错误时明确提示，关闭 AI 后基础功能仍可使用。

接入方式的后续调整：

> 把 AI 配置放到网站内，提供服务地址、模型、API Key、测试连接、保存和启用开关，避免每次修改环境文件。测试连接不要保存配置或发送论文内容；保存后立即生效，刷新页面不回显密钥。

结果：完成 AI 服务适配、输入预算和网页配置。生成与正式写入分开验证，异常和模拟服务测试通过；真实模型的认证与输出质量另行联调。

## 8 阅读工作台与界面调整

> 参考阅读工作台概念图调整界面，使用暖白与墨绿配色，让 PDF 和笔记成为主体，减少卡片套卡片、冗长按钮和默认后台控件感。
>
> 提供专注原文、对照阅读、专注笔记三种布局，保留分栏拖动和宽度记忆。选中文字后可摘录、AI 解释或高亮，笔记保存附件、页码和来源位置，点击来源回到原文。文献库同步整理搜索区、卡片密度和信息层级，保留全部已有功能。

结果：完成连续阅读、布局切换、摘录与原文联动，以及文献库和首页的视觉调整；保留阶段截图与浏览器验证记录。

## 9 笔记交互与最终完善

> 继续完善随读随记：新建笔记默认关联当前页，也允许全文笔记和手动页码。已有草稿时，后续摘录应追加到当前笔记，保留我已经写下的理解；跨页摘录各自保留来源，重复摘录不要重复添加，另建笔记时保留原草稿。
>
> 详情页和阅读器应共享草稿，收起、跳转和刷新后能恢复，保存成功再清理。请兼容旧 Markdown 和旧摘录，用户在外部修改正文后，不要用旧元数据覆盖。

批注与交互的补充指令：

> 文字批注需要支持移动、调整大小、字号与颜色，并在缩放和重开后恢复。请检查“修改字号 → 删除批注 → 撤销删除 → 再撤销字号”的连续操作，恢复批注后历史记录仍应指向正确对象。页码只在回车时跳转，切换阅读布局保留当前笔记页签。

收尾要求：

> 运行后端完整测试、前端测试、类型检查与生产构建，并用独立数据验证文献、标签、笔记、附件、统计及阅读工作台的完整流程。发现问题先复现再修复，最后说明修改内容、实际验证结果和验证范围。

结果：完成多段来源、草稿恢复、旧数据兼容与批注连续撤销等验证。后端 253 项、前端 58 项测试通过，类型检查与生产构建通过。
