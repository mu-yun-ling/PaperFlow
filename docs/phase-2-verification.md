## API 清单

**本轮新增 API：0 个。** 以下均为第一阶段已存在、本轮完成复核的接口。前缀为 `/api`。

| 功能 | 方法与路径 | 成功状态 |
| --- | --- | --- |
| 新增文献 | POST /papers | 201 |
| 文献列表 | GET /papers | 200 |
| 文献详情，含标签与笔记 | GET /papers/{id} | 200 |
| 编辑文献，可整体替换 tag_ids | PATCH /papers/{id} | 200 |

| 新增标签 | POST /tags | 201 |
| 查询标签，含文献数量 | GET /tags | 200 |
| 删除标签及其文献关联关系 | DELETE /tags/{id} | 204 |
| 为文献添加标签（幂等） | PUT /papers/{id}/tags/{tag_id} | 200 |
| 移除文献标签（幂等） | DELETE /papers/{id}/tags/{tag_id} | 204 |
| 查询文献全部笔记 | GET /papers/{id}/notes | 200 |

成功 JSON 统一使用 `{"data": ...}`；204 删除响应无正文。错误统一使用 `{"error": {"code": "...", "message": "...", "details": {}}}`。非法输入 400、不存在资源 404、重复内容 409。已有接口字段和成功响应格式保持不变。

## 实际发现与修复

提交 `tag_ids: [9223372036854775808]`，或请求 `/api/papers/9223372036854775808` 等路径时，原代码直接把超过 SQLite 64 位整数范围的值交给数据库，触发 `OverflowError`，返回 500。

新增测试先复现了 14 个失败用例。修复后，路径中的超范围 ID 返回 404 / NOT_FOUND；JSON 标签 ID 超范围返回 400 / VALIDATION_ERROR。修改在字段写入前被拒绝，已有文献、标签、笔记不受影响。其余 13 个新增业务用例在修复前即通过，未改动对应正常逻辑。

## 新增重点验收

- 文献所有可编辑字段的保存与详情回读，清空可选 DOI、年份、链接及标签。
- 编辑时拒绝空标题、空作者、非法年份、非法 DOI 和标签 ID，原数据及时间戳保持不变。
- 编辑时标题标准化去重、DOI 大小写和 URL 前缀标准化去重；冲突时标签与其他字段一并保留。
- 同一文献多个标签、同一标签关联多篇文献；删除其中一篇后，共享标签和另一篇的笔记仍存在。
- 每篇文献查询自己的笔记；空笔记不能新增或覆盖已有内容，归属文献不存在时不能创建笔记。
- 删除标签不删除文献与笔记；数据库直接 DELETE 文献时，外键也能清理笔记和关联关系。
- 真实 HTTP 验证全部 14 个方法/路径组合、JSON 响应格式、删除的空响应及非法/重复输入。
