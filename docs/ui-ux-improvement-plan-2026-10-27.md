# PaperFlow 界面与阅读体验待修改方案

日期：2026-10-27。状态：已按方案完成最终阶段修改，实施与验收结果见[最终阶段记录](phase-9-verification.md)。

以下保留实施前的排查结论与目标交互，作为开发记录。“带批注导出”按原方案仅补充结果说明，当前下载仍为原始 PDF。

## 1. 排查范围与结论

核查了当前工作区代码，以及 `http://127.0.0.1:5175` 的独立示例环境，实际查看了首页、文献详情、阅读工作台、在线笔记和文字批注。示例环境与正式文献库分离。本次只新增这份方案，没有修改业务代码。

当前最需要完善的是“阅读—摘录—写理解—回原文”的连续操作，以及草稿和批注的可编辑性。保留暖白、浅绿、墨绿的现有视觉方向，调整信息层级、可读性和操作反馈。

证据标记：

- **实测**：本次在独立示例页面复现。
- **代码确认**：当前实现中能直接确定，未逐条做浏览器操作。
- **优化建议**：现有功能可以使用，但有明确的体验改善空间。
- **待验证**：专项场景尚未完成验证，不当作已复现缺陷。

优先级：**P0 为首批必改，P1 为紧随其后的交互与视觉完善，P2 为后续效率优化**。

## 2. 首批必改：用户反馈的三项与草稿保护

### P0-01：笔记第一行改为“关联页码”，手动记录也能回原文

**现状：实测 + 代码确认。** 新建笔记显示“手动笔记 · 无页码关联”，第一项输入是“章节（选填）”。手动记录没有绑定、补填或修正页码的入口；当前页虽然传到了笔记组件，却没有用于初始化手动笔记来源。

**待改行为：**

1. 第一行改为 `关联页码 [ 2 ] / 8  [使用当前页]`，撤掉章节输入的首要位置。
2. 在阅读器内新建，默认关联创建时正在看的页码；创建后继续翻页，不自动改变该笔记的页码。
3. 支持手动修改页码；保存前校验整数及 `1～总页数` 范围。
4. 在文献详情中新建，有 PDF 时可指定页码；可提供“使用上次阅读页”，但不默认声称这是当前阅读页。
5. 保留“全文笔记／不关联页码”选项，供整篇总结使用；没有 PDF 时正常记录全文笔记。
6. 页码卡签直接显示 `P.2`，点击可回原文。旧笔记的章节内容继续保留，可放到展开信息或兼容字段中，不能直接丢弃。
7. 仅关联页码不生成文字高亮；手动页码定位与精确选区定位要区分。

**验收：** 停在第 5 页手动新建，只写理解并保存，卡片显示 `P.5`；关闭重开后可定位第 5 页；将关联页改为第 3 页后可定位第 3 页；全文笔记不会出现误导性的跳转入口。

### P0-02：编辑笔记时，摘录可以加入当前草稿

**现状：实测 + 代码确认。** 已有草稿时选中原文，点击“摘录到笔记”只提示“当前已有未保存的笔记，请先保存或取消”，不带入摘录。当前实现只对同一摘录的 AI 解释提供了追加特例。

**待改行为：**

| 当前状态 | 选区操作 | 结果 |
| --- | --- | --- |
| 没有正在编辑的笔记 | 摘录到笔记 | 新建草稿，带入选区、页码和精确位置 |
| 已有当前草稿 | 加入当前笔记 | 追加一条摘录，保留已写理解和已有摘录 |
| 想另记一条 | 另建笔记 | 先保留当前草稿，再切换到新草稿；不要求先完成当前笔记 |
| 相同片段重复点击 | 再次加入 | 提示已加入，避免产生重复摘录 |

- 有草稿时，选区主按钮明确显示“加入当前笔记”。
- 原文摘录按片段组织，每段保留自己的页码与位置；第 2 页、第 5 页的摘录可以出现在同一条笔记中。
- 跨页追加不能把整条笔记原有页码悄悄改成最新摘录页码。每个片段独立“查看原文”；卡片可展示 `P.2、P.5`。
- 删除或替换一段摘录，不影响其他摘录和“我的理解”。
- AI 解释加入用户指定的当前草稿，保留用户文字，避免只能匹配完全相同摘录才能使用。

**验收：** 手动写下理解 → 摘录第 2 页 → 追加第 5 页另一段 → 保存 → 重开，理解与两段摘录均完整；分别点击来源能回到各自位置；不再出现必须先保存或取消才能摘录的阻断。

### P0-03：文字批注支持移动、调整文本框和字号

**现状：实测编辑界面 + 代码确认。** 点击已有文字批注只弹出文字编辑框。位置只有 `x/y`；文本框宽度固定为页面宽度的 22%，没有拖动、尺寸控制柄或字号入口。后端也只保留 `x/y`，单独增加前端尺寸样式无法持久化。

**待改行为：**

1. 选择模式下单击批注，显示选中边框、拖动区和缩放控制柄。
2. 拖动可调整页内位置；拖动边角调整文本框宽高，文字自动换行。
3. “框大小”和“文字大小”分开控制，提供字号与颜色设置；编辑旧批注也能修改这些属性。
4. 双击或明确的“编辑文字”操作进入文字编辑，避免每次想移动都先弹出窗口。
5. 限制批注在页面边界内，设置最小尺寸；长文字有明确的展开或溢出处理，不能静默裁掉内容。
6. 拖动中即时预览，松手后保存；失败保留可恢复状态并提示重试。
7. 支持撤销／重做；选中后方向键微调，输入文字时快捷键不抢走编辑操作。
8. 坐标、框尺寸和字体大小使用与 PDF 页面有关的稳定单位，缩放、调整分栏及重开后保持位置与比例。

**验收：** 同一批注能移动、变宽、变高、改字号和颜色；在不同缩放比例及分栏宽度下仍对齐；刷新和重开后恢复；旧批注无需重建即可继续编辑。

### P0-04：统一草稿保留，修复站内跳转丢内容

**现状：实测。** 文献详情页新建笔记并输入内容 → 点击侧栏“文献库” → 浏览器返回，草稿消失，过程中没有未保存提示。现有 `beforeunload` 提示覆盖刷新或关闭，未覆盖站内 Hash 导航。

**代码还确认了相关风险：** 详情页和阅读工作台各有一份笔记编辑状态；关闭阅读器会触发详情刷新，而详情在 `loading` 时替换整段内容，存在详情草稿被卸载的路径。该刷新路径尚未单独做浏览器复现。

**待改行为：**

- 按文献和笔记保存本地草稿，详情与阅读器共享；再次进入显示“恢复草稿／放弃草稿”。
- 明确区分“草稿已保存在本机”和“笔记已保存”，不能让本地草稿提示看起来像已经提交成功。
- 覆盖站内导航、浏览器前进后退、阅读器关闭和页面刷新。
- 保存成功才清除对应草稿；请求失败保留全部输入。
- 按实际修改判断是否需要提醒，打开一个空白编辑器再取消不必弹确认。
- 旧 Markdown 编辑器也使用同一套草稿保护；其当前关闭逻辑直接退出，应一并处理。
- 背景刷新保留现有界面和编辑器，避免为了更新阅读进度卸载整页。

**验收：** 在详情或阅读器里写到一半，跳转、返回、刷新和关闭重开都可恢复；保存失败后仍可继续修改；空白草稿可直接退出。

## 5. 建议的笔记界面

正常写作时只把必要信息放在眼前：

```text
新建阅读笔记                         草稿已保存在本机

关联页码  [ 2 ] / 8   [使用当前页]   [全文笔记]

我的理解
┌────────────────────────────────────────┐
│ 用自己的话解释、记录疑问和公式……        │
└────────────────────────────────────────┘

原文摘录 · 2 段                           [收起]
  P.2  Reading connects new evidence…    [查看原文]
  P.5  An excerpt is a starting point…   [查看原文]

[添加标签]  [预览]
──────────────────────────────────────────
                        [取消] [保存笔记]
```

“使用当前页”只在有实际阅读上下文时出现。片段页码保留自己的来源；全文笔记可以拥有多段来源，顶部不强行伪装成只有一个来源页。

## 6. 实施顺序与涉及范围

### 第一批：形成完整的记录闭环

先落地 P0-04 草稿保护，再一起完成 P0-01 页码与 P0-02 摘录追加，随后完成 P0-03 批注变换。P1-01 布局切换应随这一批修复，避免新编辑流程继续被切换操作打断。

涉及笔记编辑、来源解析、阅读器选区动作、详情与阅读器之间的草稿状态；文字批注则需要前端交互、类型及后端几何校验同时改动。

### 第二批：提高阅读与标记效率

完成 P1-02～P1-06：标记语义与撤销、精确回跳、编辑区收敛、笔记检索与字体层级。先确定操作行为，再统一视觉细节。

### 第三批：打磨跨页面体验

完成 P2-01～P2-03；P2-04 先补下载结果说明，带批注导出单独估计工作量，不阻塞前两批。

### 数据兼容要求

- 笔记当前只有一个来源、一个摘录字符串。为跨页追加引入带版本的多摘录结构，每段包含文字、附件、页码与可选选区；保留可读 Markdown 正文。
- 单独表达手动页码关联，不能把手动笔记伪装成文本高亮。修改手动关联页码时，不携带原页失效的选区坐标。
- 兼容旧结构化笔记、旧摘录模板及普通 Markdown；不为了升级重写全部旧笔记。旧章节保留，不再作为首行必填或优先输入。
- 文字批注现有几何字段是 JSON，可扩充宽高、字体尺寸等属性；后端校验必须放行并约束这些属性。旧批注缺少属性时按兼容默认值显示。
- PDF 来源仍绑定具体附件。替换原文后明确显示“原文件已替换，需重新关联”，不能把旧坐标自动套到新 PDF。

## 7. 验收与待专项验证

实施后的关键验收流程：

1. 手动记录 → 默认页码 → 修改页码 → 保存 → 重开 → 回原文。
2. 草稿写到一半 → 同页追加摘录 → 跨页追加 → 保存 → 每段独立回跳。
3. 详情与阅读器之间切换，站内导航、前进后退、刷新、关闭重开均可恢复草稿。
4. 文字批注移动、缩放、改字号／颜色 → 撤销重做 → 重开 → 缩放 PDF 后核对。
5. 高亮、画线、文字和笔记来源提示分别检查显示、选择与删除语义；失败后可恢复。
6. 保存失败、慢请求与重复点击不丢输入、不重复创建；保存状态与实际结果一致。
7. 旧笔记、旧文字批注、无 PDF、原文替换后仍能正常显示和编辑。

**待专项验证，不视为本次已复现问题：**

- 390×844、768×1024、1280×720、1440×900；触屏及软键盘打开后保存入口是否可达。
- 当前窄屏 CSS 存在多处阅读区高度规则（42vh、55vh 等），后续应合并为明确的布局规则，并实测原文／对照／笔记三种模式。
- 长篇 PDF、大量标记和长时间拖动分栏时的流畅度；大列表中的检索与定位。
- 页码输入框失焦会调用跳页；需专项检查输入过程中点击其他工具是否导致意外跳转。
- 跨页拖选、多栏文字及扫描 PDF 的选区反馈；不能把不可选文字表现成按钮失效。

本次是排查与方案编制，没有重新运行完整测试，也未把上一阶段验收结果当作本次的新验证。实施时应补上上述交互回归；现有来源编解码与坐标测试继续保留。
